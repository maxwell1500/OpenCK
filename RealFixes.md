## 9. Remaining long-tail (surfaced by the reader diagnostics)

Loading full Starfield.esm (~3.8M indexed, ~130k materialized in tests)
produces ~1250 warnings (~1% of records) where a loader leaves bytes
unconsumed. The affected records are large/compressed master records:
huge worldspaces (lc133world, akilacity, ...), leveled ship lists, and a
subset of complex NPCs/containers. They parse without crashing and are not
written back on save (masters are not emitted unless edited). These are
size-accounting quirks to triage with the new W1 diagnostics; the plan's
W2 audit table should track them to zero.

## 2. Why this is a bigger problem than a bug list

The user is right: the individual fixes above are symptoms of structural gaps.
The evidence:

| Structural gap | Scale |
|---|---|
| Hand-written per-record parsers with no enforced bounds or layout spec | **201 record loaders** in `libs/files/esm/`; we fixed 6 of them, and only because we could hexdump the input |
| Flat fields + FormComponents + rawSubRecords triple bookkeeping | nearly every record struct has fields `load()` never fills and `save()` invents layouts for (e.g. `QuestRecord` stages, `NpcRecord` ai*, `WorldspaceRecord` cellIds) |
| Save path is never verified against the original bytes | no round-trip byte-diff test exists; the TES4 header corruption went unnoticed through every test |
| UI edits not wired to the data model | 9 of 128 files in `src/view/window/` touch `UndoStack`/`EditRecordCommand`; Weather/Water/Reference-properties editors silently discard edits |
| Fabricated identities | `ObjectPalette` allocates REFR formIds from `0x80000000`; `Data::createNewRecord` from `0x4000 + type` |
| No real-data gate | the only real-data test skips when `C:/XboxGames/Starfield` is absent; CI never parses a real master |
| Deferred-master UX | categories look empty ("one worldspace") until expanded; materialization is synchronous on the UI thread with no progress |

The common root cause: **there is no enforced contract between the format
layer, the model layer, and the UI layer, and no verification loop.**
Every new record type re-implements the same mistakes by hand.

## 3. Principles (the contracts to enforce going forward)

1. **Subrecord reads are always bounded.** `ESMReader::readType/readRaw/readZString`
   must never advance past `subLeft`; overruns throw or fall back to raw
   preservation. A loader that consumes a subrecord must consume exactly
   `subLeft` bytes or stash the remainder as raw.
2. **Raw preservation is the default.** Any subrecord without a parsed model
   goes to `rawSubRecords` untouched (198/201 loaders already do this; make it
   201/201 and mechanical).
3. **Load/save symmetry.** Every subrecord `save()` writes must be either
   (a) replayed raw bytes, or (b) written from a field that `load()` populated.
   No invented layouts.
4. **Single source of truth per record.** Components own parsed fields; the
   flat mirror fields exist only where external code needs them, and are
   populated from components in exactly one place. `blank()` must never clear
   a field `load()` never fills.
5. **Every UI edit goes through the UndoStack.** Editors modify the record
   through `EditRecordCommand` (or equivalent), never local copies.
6. **FormIds come from the document, not from constants.** Allocation uses
   the plugin's load-order index, is sequential, collision-checked, and
   undoable.
7. **Real data is the test corpus.** Every record type must be exercised
   against real masters (Starfield.esm, Magnus.esm, SeydaNeen.esp available
   on this machine) plus a saved synthetic fixture, in CI.

## 4. Workstreams

### W1 — Reader invariants and diagnostics (foundation)

Goal: make misparses fail loudly instead of silently corrupting data.

Tasks:
- `libs/files/esm/esmreader.cpp`: add `readBounded` checks to `readType`,
  `readRaw`, `readZString` (when `subLeft > 0`, refuse to read past it;
  log a warning and return zeros/padded bytes; Debug builds assert).
- Add a per-record consumption check: when a record loader returns, if
  `recLeft != 0` and the remainder was not raw-preserved, log
  `LOG_WARNING` with record type + formId + offset. Run it against the
  full real-data matrix (W7) and drive remaining misparses to zero.
- Add a `--esm-strict` mode to the CLI that turns warnings into failures.
- Replace the remaining `readType<quint32>()`-then-loop-over-it patterns
  (audit: `conditionrecord.cpp`, `navmrecord.cpp` already use subLeft-
  relative counts and are OK; re-verify) with `subLeft`-derived counts.

Acceptance: loading Starfield.esm fully (see W7) produces a bounded,
triageable warning list; no silent desyncs.

### W2 — Parser audit against format specs

Goal: every one of the 201 loaders matches documented layouts for
Morrowind/Skyrim/FO4/Starfield (UESP + xEdit `wbDefs` as reference).

Tasks:
- Build a layout table in `docs/record_formats.md`: for each record type,
  per-game subrecord name, size, struct layout, and OpenCK parse status
  (parsed / raw-preserved / broken). Generate the skeleton mechanically
  from the loaders' switch cases, then fill in from specs.
- Triage all loaders into: `OK`, `raw-only (fine)`, `parsed-wrong`.
  Fix `parsed-wrong` in priority order: records users edit most
  (NPC_, WEAP, ARMO, SPEL, ENCH, ALCH, CELL, WRLD, QUST, PACK, INFO,
  DIAL, FACT, PERK, RACE, STAT, CONT, BOOK, MISC, LIGH, KYWD, OTFT,
  COBJ, LVLI, NPC_/CREA actor data, NAVM, LAND, SCEN).
- Known broken fields to fix (from the audit):
  - `QuestRecord`: stages (INDX/QSDT/CNAM...), objectives, aliases — load + save + UI.
  - `WorldspaceRecord`: cell list derivation (cells belong via CELL records;
    add `Data::cellsInWorldspace(worldspaceId)` and use it in
    `cellsdialog.cpp`, `celltransitionseditor.cpp`).
  - `NpcRecord`: ai* fields — parse or remove; never display zeroed junk.
  - `CellRecord`: remove the 500-iteration guard (AGENTS.md already says so).
  - `DialRecord`/`InfoRecord` relationship walking (INFO groups under DIAL).
- All fixes land with a fixture test (W7) per record type.

Acceptance: the layout table shows no `parsed-wrong` rows; each fixed type
has a round-trip test.

### W3 — Save-path integrity

Goal: saving a plugin that was only opened must produce a byte-identical
(or subrecord-identical, minus the record count) file.

Tasks:
- Corpus round-trip: for every file in the user's data dir
  (Starfield.esm, Magnus.esm, SeydaNeen.esp + any others), load fully
  (all types), save to a temp file, then:
  - compare record count, order, subrecord names and payloads
    (a "subrecord diff" tool in `tools/` or a test helper);
  - report every differing subrecord per type and drive to zero for the
    untouched-record path.
- TES4/HEDR header: verify numRecords, nextObjectID, masters, INTV.
- Fix `ESMWriter` gaps found: header flag round-trip for ESL/ESM
  (partially done), GRUP writing for CELL children (REFRs must be
  written into the right GRUPs — currently uncertain; verify against
  real CELL structure).
- Component save() format conversions (TESAttributes BYDT→ATTR,
  TESSkills skipping zero values, TESBipedModel CNAM/BNAM merge,
  BGSSoundDescriptor SNDD/SNDX) — preserve the loaded subrecord format
  per game.

Acceptance: untouched-file round-trip has zero payload diffs for all
record types in the corpus; a test fails the build otherwise.

### W4 — Model cleanup (single source of truth)

- Document state machine: verify `State_Base/Modified/ModifiedOnly`

Acceptance: no `blank()` clears a field that no loader fills; no UI

### W6 — Deferred-master UX (Object Window / worldspaces)

Goal: expanding the Object Window shows real counts and never freezes
or crashes.

Tasks:
- Move `ensureTypeLoaded` off the UI thread: run materialization in the
  loader thread (or a worker), signal completion, then insert rows
  (current in-place `beginInsertRows` stays). Keep the model immune to
  resets during view operations (the W1 crash fix must not regress).
- Show pending counts in the category label before expansion
  (e.g. "Worldspace (441)") so the tree doesn't look empty/fake.
- Progress indication for large types (INFO is 126k records;
  STAT/CELL/etc. will be bigger) — reuse the Loader's stage signals.
- Handle save-during-deferred state: materialized master records must
  not be written out as overrides unless actually edited (W4 state
  machine).
- Sort merged plugin+master records consistently (editorId/formId).

Acceptance: on this machine, open SeydaNeen with masters, expand every
Object Window category: no crash, no freeze >200ms per UI slice,
correct totals, edits to master records produce correct overrides.

### W7 — Test infrastructure and CI gates

Goal: the fixes can't silently regress; real data is always exercised.

Tasks:
- Introduce `OPENCK_DATA_DIR` (default `C:/XboxGames/Starfield/Content/Data`)
  honored by all real-data tests; keep `QSKIP` only when absent.
- A "materialization matrix" test: for every CkId type, index count vs.
  loaded count vs. warning count from a full master load; assert
  warnings == 0 (or an explicit allowlist that shrinks over time).
- Per-type round-trip tests: load each record type from the corpus,
  save untouched, diff subrecords (W3 helper).
- The fake-data lint: a CI grep that fails on hardcoded game content
  strings in `src/` (record names, location names, `addItem("...")`
  with content literals), forcing sample data to come from fixtures.
- Editor write-back smoke tests (W5 acceptance) as part of the suite.
- Keep the full suite (107 exes) green; wire into the documented
  `cmake --build` + test loop.

Acceptance: a machine with the data dir runs the full suite incl.
real-data gates in CI-able time (currently ~3.5s for 5 types; budget
<60s total for the matrix, running the heavy types once per build).

## 6. Definition of done

- Full corpus load (all types, all files) runs with zero reader warnings
  (or a documented shrinking allowlist).
- Untouched-plugin round-trip is payload-identical per type.
- Every editor dialog persists via UndoStack (automated smoke tests).
- Object Window: expand-any-category without crash/freeze, correct counts.
- No hardcoded game-content strings or fabricated IDs in `src/`.
- 107/107 existing tests + all new gates green, on this machine and CI.

## 7. Risks

- **Format documentation gaps**: Starfield-specific subrecords are only
  partially documented publicly; the audit must be empirical (hexdump +
  xEdit comparisons) where specs are missing. Acceptable: raw-preserve
  unknown subrecords and document them as such.
- **Changing reader invariants may surface hundreds of latent misparses**
  in loaders we haven't touched. Mitigate: warnings first (not failures),
  triage with the matrix test, fix in priority order.
- **GRUP writing on save** (CELL children groups) is untested; the
  round-trip diff will expose it. Plan for a focused investigation.
- **Threading the materialization** (W6) touches the Loader/mediator
  protocol; keep the current synchronous path as a fallback flag.
